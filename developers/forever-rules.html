What the Forever client allows

WoW Forever runs Classic content on the modern client (interface 16001). That client limits add-ons in ways Classic add-on authors don't expect. This page collects what the suite has learned. The evidence is ForeverAPI Probe's runs on 2026-11-07, recorded in the Forever API reference (its Restrictions page, and one page per API system). Probe your own calls there before you build on them.

The helpers named here (Core.IsSecret, Core.Plain, Core:AfterCombat, ...) are LibForever-1.0's too, under the same names (LibForever.IsSecret, ...), for add-ons outside the suite. UI.* and Core.Guild are Norgannon Core's own.

Never

Don't Why
Call any C_Housing*, C_House* or C_Neighborhood* function It can crash the client (ACCESS_VIOLATION), even with no arguments
Register COMBAT_LOG_EVENT or COMBAT_LOG_EVENT_UNFILTERED ADDON_ACTION_FORBIDDEN. There's no combat log for add-ons. Count kills from XP or loot instead
Register UNIT_PING_PIN_ADDED / _REMOVED Forbidden
Call C_Discord.* getters, C_Navigation.GetNearestPartyMemberToken or C_SocialRestrictions.IsAgeVerificationRestrictedMinor Forbidden
Compare, add, concatenate, index or tostring a value that may be secret It errors. See below

Secret values

A secret value can be stored and handed to a widget, but not inspected. Check with Core.IsSecret(v), read with Core.Plain(fn, ...) (secrets become nil), and hand raw values to widgets with Core.SetSecret(widget, method, v).

Always secret, in and out of combat: UnitHealth, UnitHealthMissing, UnitHealthPercent, UnitPower, UnitPowerMissing, UnitPowerPercent, UnitPartialPower, UnitGetIncomingHeals, UnitGetTotalAbsorbs, UnitGetTotalHealAbsorbs, UnitInRange, UnitPercentHealthFromGUID, UnitThreatPercentageOfLead, UnitSpellTargetName.

Core does this for you: UI.UnitBar (health and power), Core.Secret (curves, text, show-if, colours) and UI.UnitAuras (auras in combat, drawn by the game). By hand, widgets take them as they are: StatusBar:SetValue, SetMinMaxValues, FontString:SetFormattedText("%d", v), SetAlphaFromBoolean, and colour curves (UnitHealthPercent(unit, true, curve) gives a colour or alpha you pass on). Mercy's unitframe.lua is the worked example.

Secret in combat: about 55 character-stat getters (GetCritChance, GetHaste, GetMastery, UnitArmor, UnitAttackPower, UnitDamage, UnitStat, GetUnitSpeed, UnitIsCharmed, ...), action and spell cooldown durations (C_Spell.GetSpellCooldown().duration), and display counts.

Unit identity goes secret all at once for some units (C_Secrets.ShouldUnitIdentityBeSecret): UnitName, UnitFullName, UnitGUID, UnitRace, UnitClass and UnitPVPName together. Nameplate units are where this bites.

Errors in combat (for add-on code)

These calls error in combat with "Auras cannot be accessed when secret while tainted", even for "player": C_UnitAuras.GetUnitAuraInstanceIDs, GetUnitAuras, GetAuraDataByIndex, GetAuraDataBySlot, GetBuffDataByIndex, GetDebuffDataByIndex, GetAuraSlots, and C_TooltipInfo.GetUnitAura / GetUnitBuff / GetUnitDebuff. Read auras out of combat and keep the answer, or let Blizzard draw them (C_UnitAuras.AddPrivateAuraAnchor, as Mercy does).

C_GuildInfo.GetMOTD, GetInfoText, GetGuildRosterMOTD and GetGuildInfoText are blocked in combat.

Knowing when you're restricted

  • InCombatLockdown() is the reliable combat test. C_RestrictedActions.IsAddOnRestrictionActive(Enum.AddOnRestrictionType.Combat) read false during open-world combat, so never use it alone.
  • Restriction kinds: Combat 0, Encounter 1, ChallengeMode 2, PvPMatch 3, Map 4, Chat 5, plus the event ADDON_RESTRICTION_STATE_CHANGED. Map only means you're on a map with restrictions, and Chat covers add-on chat. Neither stops moving items.
  • Protected work (secure buttons, their attributes, showing or moving protected frames) waits with Core:AfterCombat(fn, key). The Settings window doesn't open in combat either: A:OpenSettings() from Core:NewAddon waits for you.

Chat and add-on messages

  • CHAT_MSG_SYSTEM, _WHISPER, _GUILD, _OFFICER, _PARTY*, _RAID*, _SAY, _EMOTE, _YELL, _CHANNEL and _TEXT_EMOTE are secret during chat lockdown. CHAT_MSG_LOOT and CHAT_MSG_ADDON are not.
  • C_ChatInfo.AreOutgoingAddonChatMessagesRestricted is about add-ons sending chat. Add-on messages may still flow. C_ChatInfo.SendAddonMessage returns an Enum.SendAddonMessageResult (0 to 12) that says why a send failed.
  • ChatThrottleLib holds messages for its first 5 seconds after login.
  • Use C_ChatInfo.SendChatMessage. The old global exists too, but the namespaced call is the one that stays.

Names

Forever characters have a first and a last name.

  • The guild roster and UnitName give the first name. Chat senders and GetUnitName("player", true) give "First Last".
  • A whisper to a first name alone fails ("No player named ..."). Keep the full name you saw in chat, or the sender of an add-on message, to reply to someone.
  • Core.Guild.Short(name) turns any form ("Tyrant Kuma", "Tyrant-Realm", "Tyrant") into the first name, which is the key the roster uses.

Maps and position

  • Coordinates come from Core.Player:GetPosition() and Core's copy of HereBeDragons, patched for Forever's Classic map hierarchy. Don't call C_Map directly for the player's position.
  • C_Map.GetBestMapForUnit("player") works in the open world (checked in game, 2026-11-07: 1413). It returns nil, and so does UnitPosition, where the Map restriction is active (ApiProbe's run) and in instances. Handle nil.

Other client facts

  • GuildRosterSetOfficerNote doesn't exist. Notes go through C_GuildInfo.SetNote, which is restricted.
  • The guild finder is off on Forever.
  • Modern strlower(...) returns every argument it's given: strlower(UnitClass("player")) passes two strings on.
  • Interface/ui-code-list.txt in the game's CASC lists every Blizzard UI file, and any CASC reader can list it.
