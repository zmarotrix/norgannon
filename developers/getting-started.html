Building an add-on on NorgannonDB Core

The API is in ../core-api.md, and what the Forever client allows is in forever-rules.md. NorgannonTemplate is a small, complete example that the suite's tests keep working.

The Forever toolkit: problems Core solves for you

WoW Forever runs Classic content on the modern client, and that trips add-ons in ways Classic authors don't expect. These are the ones Core handles; forever-rules.md has the evidence.

On Forever... Use
GetSpellInfo, GetItemInfo, GetContainerItemInfo and dozens more classic functions don't exist Core.Compat.GetSpellInfo(...) and the rest: the classic answers, no globals written
WOW_PROJECT_ID is 18 (WOW_PROJECT_CAMELOT), neither Classic nor Retail Core.Client.IsForever(), Core.Client.Flavor(), Core.Client.IsClassicWorld()
health is always secret, and in combat so are cooldowns, charges, stats and threat UI.UnitBar for health and power; Core.Secret for curves, text, show-if and colours
add-ons can't read auras in combat (the call errors) UI.UnitAuras(parent, unit): the game draws them in your frame
protected frames can't change in combat Core:AfterCombat(fn, key)
"are we in combat?" from the restriction API reads false in open-world combat Core:Restricted("combat" \| "fight" \| "send") and the message NORGANNON_RESTRICTIONS_CHANGED
characters have first and last names; a whisper to a first name fails Core.Names.First(name) to tell who someone is, Core.Names:Address(nameOrUnit) to reach them
add-on messages are lost if sent during chat lockdown Core.Net:Channel(prefix, { onMessage }): held and sent when it lifts, compressed, refusal detected
a chat line from an add-on may not arrive (in instances especially) Core:Say(text, kind): sends it, and if it never shows, opens the chat box with it ready
the player's map position needs Forever's Classic map hierarchy Core.Player:GetPosition() (nil where the game gives none, such as instances), and Core's map pins
testing combat behaviour needs the game tools/harness/secrets.lua: secrets and combat lockdown in the stub client

The TOC

## Interface: 16001
## Title: |cff9fd0ffLantern|r
## Category: NorgannonDB
## Version: 0.1.0
## Dependencies: NorgannonDB_Core
## SavedVariables: LanternDB
## AddonCompartmentFunc: Lantern_OnAddonCompartmentClick
## AddonCompartmentFuncOnEnter: Lantern_OnAddonCompartmentEnter
## AddonCompartmentFuncOnLeave: Lantern_OnAddonCompartmentLeave

List NorgannonDB in Dependencies only if you read the game data (Core.DB, Core.Map or NorgannonDB). It's 52 MB on disk and about 33 MB of game memory, and Core runs without it.

core.lua

local ADDON = ...
local Core = NorgannonCore
if not (Core and Core.NewAddon) then print("Lantern needs NorgannonDB Core 1.20 or newer.") return end

local A = Core:NewAddon("lantern", {
  folder = ADDON, api = { 1, 20 },
  name = "Lantern", accent = "9fd0ff", role = "Lights the way",   -- only for add-ons outside the suite's registry
  db = "LanternDB", version = 1, defaults = { shown = true },
  slash = { "/lantern" },
  commands = { reset = { function() A.Window:ResetPosition() end, "put the window back" } },
})
if A.disabled then return end

function A:Toggle() A.Window:Toggle() end   -- left-click and /lantern alone

That gives you: - the version check, with one line in chat if this Core can't serve you - A.db with your defaults, plus version and migrate for changes later - A:Print, and A:Send/A:Listen on Core's message bus - the slash command with help - a row in the Norgannon minimap flyout and the game's add-on menu: left-click runs A:Toggle(), right-click opens settings - A:AddSettingsPage(frame) and A:OpenSettings(), which waits for the fight to end in combat

Other files start with local A = Lantern; if not A or A.disabled then return end.

Versions

api = { 1, 20 } means "written for Core 1.20". It runs on any later 1.x: a minor version only adds. A new major version may change things.

Rules

  • Events go through Core:On(event, owner, fn).
  • Call the game through Core.Global, Core.In and Core.Plain, which turn errors and secret values into nil.
  • Classic functions the client no longer has (GetSpellInfo, GetItemInfo, GetContainerItemInfo and more) are in Core.Compat, with their classic return values. Core.Client.IsForever() tells Forever apart, whatever WOW_PROJECT_ID says.
  • Hand values that may be secret straight to widgets with Core.SetSecret, or use UI.UnitBar, Core.Secret and UI.UnitAuras, which do it for health, text, show-if and auras in combat.
  • Protected frames are touched only out of combat (Core:AfterCombat).
  • Use Core's colours (UI.C, UI.Accent) and widgets (UI.Window, UI.ActionList, UI.SettingsList), not your own.
  • Player-facing text says "add-on".
