NorgannonDB_Core API — version 1.26

The runtime library every suite add-on (Clairvoyance, Oracle, Retrospect, Dimension, Council, Muster, Mercy, Bulwark) builds on. It ships in the NorgannonDB download as its own folder, NorgannonDB_Core. NorgannonDB, the game data, is optional since 1.19: list it in your TOC only if you read it. The Core's code is All Rights Reserved (see its LICENSE); NorgannonDB's data is GPL-3.0. This document is the contract: anything not listed here is internal.

-- TOC:  ## Dependencies: NorgannonDB_Core   (add NorgannonDB if you read the game data)
local Core = NorgannonCore
if not Core or not Core:Require(1, 1) then return end   -- or Core:NewAddon (1.19), below

Versioning: a new function bumps the minor version, and an add-on written for 1.x runs on any later 1.x. A breaking change bumps the major version; add-ons then need updating.

Core.SafeCall(fn, ...) calls through securecallfunction, so one addon's error doesn't stop the others
Core:Print(msg[, prefix]) chat line with the NorgannonDB prefix
Core:Debug(source, fmt, ...) adds to the debug log when /norg debug is on (saved, /norg debug show)

Core messages: NORGANNON_ADDON_REGISTERED (key), NORGANNON_BAG_BUTTON_UPDATED (button) (a bag window built from the game's item buttons just filled one, so other add-ons can mark it).

Data: search and relations (Core.DB)

Reads NorgannonDB schema 1.2. Unobtainable quests (hidden == true) never appear in any of these.

Call What it does
DB:Search(text, { kinds = { quests, npcs, objects, items = true }, limit = 50 }) ranked name search over localized names: exact, then prefix, then word prefix, then anywhere; shorter names first. Same-named entities are one result. Returns { {kind = "npc", key = "npcs", name, ids = {...}, class}, ... }, totalMatches. Typing more of the same query only re-checks the previous matches
DB.indexReady, message NORGANNON_INDEX_READY (1.22) the name index builds one kind at a time, the first time a search or IdsByName asks about it (under 20 ms each); these mean every kind is built. DB:EnsureIndex([kind]) builds now, DB:IndexStats() says which kinds are built
DB:Name(kind, id) localized name without decoding the record
DB:IdsByName(kind, name) (1.7) every id with exactly that (localized, case-insensitive) name, e.g. for tooltips that only have a name
DB:IsQuestHidden(id) true if the quest can't be obtained
DB:QuestsFor("npcs" \| "objects", id) { starts, ends, objective } quest ids
DB:ItemInfo(id) { drops, vendors, rewardOf, startQuest, objective }
DB:Zone(areaId) { npcs, objects, quests }
DB:Unlocks(questId) quests it is a prerequisite of, and its nextQuestInChain

Budgets measured by the harness: a typical query over every kind takes about 3 ms; a one-letter query (35,000 matches) takes about 8 ms.

Map layer (Core.Map)

One pin layer for the suite on the world map and the minimap. Addons submit pins; the Core draws them, so addons never stack their own layers.

Call What it does
Map:SetPins(owner, pins) / Map:ClearPins(owner) replaces an owner's pins
pin fields area, x, y (NorgannonDB percent coordinates); icon; color {r,g,b} (tints pin/diamond); size (world, default 7); minimapSize (default 7); layer (draw order, higher on top); quest (a quest id: the pin takes the quest's colour, hovering dims other quests, and without an onClick a click recolours it); highlight (the group a pin without a quest highlights with); overlapKey (pins sharing it don't stack: one is skipped when another is drawn within its size on screen); cluster (group key: a dense group gets a soft glow, shown only while one of its quest's pins is hovered); compass (group key: one compass marker per group, at its nearest pin); world/minimap = false to skip one; alpha; title; tooltip(pin, GameTooltip); onClick(pin, button); (1.6) onShiftClick(pin, button) with shiftHint (a tooltip line)
icons pin, diamond (tintable); the game's own quest marks: exclaim, exclaimDaily, exclaimGrey, question, questionRepeat, questionGrey (client atlas, then the classic gossip icon, then ours); or any texture path
Map:Pulse(key[, duration]) (1.4) "show me": the pins of a highlight group (e.g. "q788") grow and shrink for a moment (default 1.6 s) while the others dim; also for pins drawn later, e.g. right after opening the map
Map:SetHighlight(key), Map:Refresh() highlights one group (nil clears), dimming the others on the world map, minimap and compass, with message NORGANNON_MAP_HIGHLIGHT (key); draws everything now rather than within the next 0.05 s
colorKey = "any:key" on a pin (1.9) colours anything like a quest: Colors:ForQuest(key) (alias Colors:For) takes any key, a click rolls a new colour, right-click opens the picker. Colors:RegisterInUse(owner, fn) lists other keys on screen so random colours avoid them
icon = "service.<category>" (1.8) the game's own icons for town services and gathering (flight, mailbox, innkeeper, banker, auctioneer, repair, vendor, trainer, stablemaster, battlemaster, spirithealer, meetingstone, chests, herbs, mines, fish): modern atlas, then the classic Minimap\Tracking file, then a spell/item icon cropped round, then our diamond. Never tinted. Map.IconSource(name) and /norg icons say which one the client has
Map:PinsIn(area), Map.Cluster(pins), Map.WorldOf(pin), Map.AreaToUiMap, Map.UiMapToArea helpers
Map.stats { world, minimap, clusters, overlapped } drawn now, and skipped as overlapping
message NORGANNON_WORLDMAP_CHANGED (uiMapID or nil, areaId) (1.5) the world map opened, closed or now shows another map
continent and world maps one marker per objective group (the centre of its spawns in each zone) and per turn-in, translated onto the continent; only quest pins (quest or compass key) show there, continent = false opts out. Tooltips add "12 spots in Durotar"

Rules the layer keeps: - World pins sit on the map canvas above Blizzard's pins (level 2015) and keep their size while you zoom. - Pins report no centre to the gamepad cursor, so they never taint it. - The minimap follows rotation, zoom, indoor maps and the minimap's shape, drawing at most the 150 nearest pins. - Coordinates come from a private copy of HereBeDragons (HereBeDragons-NorgannonCore-2.0), patched for Forever's Classic map hierarchy.

Quest colours (Core.Colors)

Every quest shows in one colour across the map, minimap, compass and Clairvoyance's tracker: a stable default from a 100-colour palette, or the player's choice (saved account-wide).

Colors:ForQuest(key) (alias Colors:For) returns {r, g, b} for a quest id or any other key. Colors:Set(key, color), Colors:Randomize(key) (avoids colours in use) and Colors:Pick(key) (the game's colour picker) change it. Colors:RegisterInUse(owner, fn) lists other keys on screen. Message: NORGANNON_QUEST_COLOR_CHANGED (key).

Compass (Core.Compass)

A strip at the top of the screen with N/E/S/W and one marker per pin group that has a compass key (its nearest pin, in the pin's colour and icon, sized and faded by distance). Hover a marker for its tooltip and distance. The arrow's focus target shows as a gold diamond.

The bar is click-through and hides where the client gives no facing (instances) or when nothing is tracked.

Compass:SetShown(on), Compass:IsEnabled(), Compass:SetMovable(on) (lit with a hint while moving; right-click locks), (1.6) Compass:SetSize(scale) / GetSize(), Compass:ResetPosition(), message NORGANNON_COMPASS_MOVING (on). Arrow:SetSize(scale) / GetSize(). Settings page "Compass & arrow" under NorgannonDB.

Waypoint arrow (Core.Arrow)

On demand only (decision 9). Arrow:SetTarget({ area | uiMap, x, y, title, owner, arrive }) returns false if the spot can't be placed. Arrow:Clear(reason) and Arrow:GetTarget() complete the API.

It turns from red (behind) through gold to green (ahead), shows yards, and clears itself on arrival. Drag it to move it; right-click dismisses it. The target survives /reload.

Messages: NORGANNON_ARROW_SET, NORGANNON_ARROW_ARRIVED, NORGANNON_ARROW_CLEARED (reason).

Party comms (Core.Comms) (1.1)

Questie-compatible party quest progress (QuestieComms message version 5: AceComm, Questie's serializer, packets 1, 2, 10, 11, 12 and 14). Questie and suite users in one group see each other's progress. The harness round-trips packets through Questie's real serializer.

  • Sending is automatic: your changes go out coalesced (one update per quest per second), and joining a group requests and shares quest logs.
  • Comms:GetParty(questId) returns { [player] = { [index] = { id, type, fulfilled, required, finished } } }.
  • Comms:ProgressFor("npcs" | "objects" | "items", id) returns { {questId, player, index, objective}, ... }. An item objective also matches the NPCs and objects that drop or sell the item.
  • Messages: NORGANNON_PARTY_UPDATED (questId, player), NORGANNON_PARTY_CLEARED.

Minimap buttons (1.13; the Norgannon button 1.18)

One Norgannon button sits on the minimap; clicking it opens a flyout with a row per registered addon (mark, name, a status line read from its tooltip). A row's left and right clicks go to the addon's onClick, as its own button's would; hovering shows its tooltip less "Drag: move"; the pin at the row's end pins it. A pinned addon also keeps its own round button. Every button drags around the minimap's edge (round and square shapes). Settings: NorgannonDB > Minimap.

API
Core.MinimapButton:Add(key, { onClick = fn(button), tooltip = fn(tt) }) registers the addon: a row in the flyout, and its own button (shown while pinned). Returns its own button
Core.MinimapButton:SetShown(key, on), :IsShown(key) the addon's "Show the minimap button" setting. Since 1.18 this means pinned: its own button on the minimap as well as its row in the flyout
:SetPinned(key, on), :IsPinned(key) the same, by its new name (1.18)
:SetMainShown(on), :IsMainShown() the Norgannon button itself (1.18)
:Status(key) the flyout's status line: the last tooltip line that is neither the name nor a click hint (a live line like "3 replies wait for you" beats the role line), else the registry's role (1.18)
Core.MinimapButton.buttons[key] the frame the addon is on screen: its own button when pinned, else the Norgannon button (anchor popups to it)
saved NorgannonCoreDB.minimap = { v = 2, angle, hidden, addons = { [key] = { angle, pinned } } }; the 1.17 per-addon entries migrate in, places kept, all unpinned

Collecting other addons' minimap buttons (Minimap Button Bag style) is not done. If it is wanted later, limit it to buttons registered with LibDBIcon, which have a known API, rather than scraping the minimap's children.

Known recipes (1.15)

API
Player:KnownRecipes(skillLine) what a profession's scan found: { ids = { [spellId] = true }, count, source = "window" \| "spells", seen }, or nil if nothing has been read
Player:KnowsRecipe(spellId) true if a scan saw it learned; nil means "not seen", not "not known"
Player:ScanRecipes() reads every profession again through IsSpellKnown, one per frame. It runs at login by itself
message NORGANNON_RECIPES_SCANNED (skillLine, count, source) after each scan

Two readers feed it: at login every NorgannonDB recipe through IsSpellKnown ("spells"), and, whenever a profession window is ready, what C_TradeSkillUI lists as learned ("window", which also holds recipes NorgannonDB doesn't have yet). Other people's linked professions are skipped. Neither reader removes anything.

Guild roster (1.17)

The guild roster, read once for the whole suite, so two add-ons don't each poll it. It only reads.

API
Core.Guild:Watch(owner) / :Unwatch(owner) keeps the roster fresh (asked for once a minute) while anyone watches; asks at once
Core.Guild:Known(), :InGuild(), :Name() whether a roster has been read, whether you're in a guild, its name
Core.Guild:Get(name) { name, full, rank, rankName, level, zone, online, class, guid } or nil. name is the first name; full is the roster's own text
Core.Guild:IsMember(name), :Members(), :OnlineCount()
Core.Guild:CanInvite() the game's CanGuildInvite
Core.Guild:RankCanInvite(rank), :Inviters() whether a rank can invite (flag 7 of GuildControlGetRankFlags, from /cprobe's data), and who online can, guild master first, never you
Core.Guild.Short(name) who someone is from any form of their name: "Tyrant Kuma", "Tyrant-Realm" and "Tyrant" are all "Tyrant"
message NORGANNON_GUILD_ROSTER (revision, joined, left) the roster changed: who joined and left since the last read, by first name (none on the first read)
message NORGANNON_GUILD_RECRUITED (name, source, by, when) sent by Muster when someone it asked joins, so another add-on can note where a member came from

On Forever, the roster and UnitName give a character's first name, while chat gives first and last, and a whisper to the first name alone fails. full isn't promised to be something a whisper reaches.

Building an add-on (1.19)

The developer guide is Getting started, and what the client allows is What the client allows. NorgannonTemplate is a small working example. Versions: an add-on written for 1.x runs on any later 1.x (a minor version only adds); a new major version may change things.

NorgannonDB is optional. Core's TOC lists it under OptionalDeps. Without it, Core.DB answers nil and empty lists, and the map, compass and quest features have nothing to draw. Add-ons that read the data list NorgannonDB in their own TOC's Dependencies.

Call What it does
Core:NewAddon(key, opts) makes an add-on part of the suite and returns its table A (also the global opts.global or the folder name). If this Core or NorgannonDB can't serve it, A.disabled is true and the player is told once. opts: folder, api = {1, 19}, data = {1, 4}, db, defaults, version, migrate, char, charDefaults, charVersion, charMigrate, slash = {"/x"}, commands = { name = fn(rest) \| {fn, "help"} }, minimap = false \| { onClick, onShiftClick, status, clickHint, shiftHint, rightHint }, and for add-ons outside the registry name, accent, role, mark
A key, name, addonName, info, PREFIX, ACCENT, ready, db, char, :Print, :Debug, :Send/:Listen/:Unlisten (messages prefixed KEY_), :OnReady(fn), :OnLogin(fn), :AddSettingsPage(frame), :OpenSettings() (waits for the end of combat), :RunCommand(msg), :PrintHelp(). Define A:Toggle() for the main action: left-click, and the slash command alone
Core:SavedVars(name, { version, defaults, migrate }) loads a saved variable: runs each migration it hasn't had, once and in order, deep-fills defaults without touching a player's values, and stores the version in _v. A save from before versioning counts as version 1, and a new save starts at version
Core.FillDefaults(target, defaults) the deep fill on its own
Core:HasData() whether NorgannonDB is loaded

Add-on messages (Core.Net, 1.21)

Messages under an add-on's own prefix. They move text: each add-on turns its data into text and back itself (Council uses its own serializer).

Call What it does
Core.Net:Channel(prefix, opts) one channel per prefix. opts: onMessage(text, first, sender, distribution) for each message from someone else; distributions (a set; default guild, officer, raid, party, whisper, instance); maxIncoming (120000); maxQueue (200); compressFrom (120); onDrain() after held messages go out

Classic functions and the client (1.23)

WoW Forever's client has no GetSpellInfo, GetItemInfo, GetContainerItemInfo and dozens more: they moved into C_Spell, C_Item, C_Container, C_SpellBook and C_AddOns, often returning a table instead of several values. Core.Compat gives them back with the classic return values. It never writes globals.

Call What it does
Core.Compat.<ClassicName>(...) the classic function's answer: the client's own global when it has one, else the replacement reshaped. 58 functions (41 by hand, 17 generated from ForeverAPI's relocated-API table by tools/compat_gen.py), listed in Core.Compat.MAP (classic name to replacement), among them GetSpellInfo (the rank is the spell's subtext), GetSpellCooldown, GetSpellCharges, GetSpellTexture, IsUsableSpell, GetItemInfo, GetItemInfoInstant, GetItemCooldown, GetItemCount, GetContainerItemInfo, GetContainerNumSlots, GetNumSpellTabs, GetSpellTabInfo, GetSpellBookItemName/Info/Texture (with "spell" or "pet"), GetAddOnMetadata, IsAddOnLoaded, UnitAura/UnitBuff/UnitDebuff, GetMouseFocus
secret values spell cooldowns and charges are secret in combat on Forever: Compat.GetSpellCooldown hands them back as they came. Pass them to widgets; don't compare them
auras add-ons can't read auras in combat (the call errors): Compat.UnitAura and friends answer nil then
Core.Client.IsForever() true on WoW Forever (interface 16000-16999). Use this, not WOW_PROJECT_ID, which is 18 there (WOW_PROJECT_CAMELOT), neither Classic nor Mainline
Core.Client.Flavor() "forever", else what WOW_PROJECT_ID says: "classic", "tbc", "wrath", "cata", "mists", "retail", or "unknown"
Core.Client.IsClassicWorld() true where the maps, zones and quests are Classic's (Forever and Classic Era)
Core.Client.Interface() the interface number (16001 on Forever 1.60.1)

Secret values and auras (1.24)

On WoW Forever health is always secret, and in combat so are about 90 other getters (cooldowns, charges, stats, threat). Add-on code may not compare, add or format a secret. It may hand one to the widget calls Blizzard marks "AllowedWhenTainted": StatusBar SetValue, SetMinMaxValues, SetStatusBarColor; FontString SetText, SetFormattedText, SetTextColor; Texture SetVertexColor, SetAlpha; SetAlphaFromBoolean on textures and frames. Not SetShown, and no Cooldown setter (those take secrets only from Blizzard's own code).

Call What it does
UI.UnitBar(parent, opts) a health (or kind = "power") bar that never reads the numbers. opts: color = {r, g, b} or "gradient" (red to green by health, through a curve); text = "current", "percent", "missing" or "none"; short (1.3K); height, textSize. :SetUnit(unit), then :Update() on UNIT_HEALTH and friends
Core.Secret.Curve(points, kind), .ColorCurve(points, kind) a number curve { {x, y}, ... } or a colour curve { {x, r, g, b[, a]}, ... }, kind "Linear" or "Step". UnitHealthPercent(unit, true, curve) evaluates one on a unit's health without your code reading it
Core.Secret.Text(fs, fmt, ...), .Number(fs, value, short, prefix) text from values that may be secret, through SetFormattedText
Core.Secret.Alpha(region, bool, on, off) show or fade by a boolean that may be secret (SetAlphaFromBoolean): the way to "show if", since SetShown won't take a secret
Core.Secret.Color(region, color), .ColorFromBoolean(bool, whenTrue, whenFalse) a colour that may be secret onto a status bar, text or texture; one of two colours by a secret boolean
UI.UnitAuras(parent, unit, opts) a container the game fills with the unit's auras, in combat too (add-ons can't read auras in combat on Forever, but the game can draw them). opts: debuffs (3), buffs (0), size (14), dispel = "mine", "any" or "off". :SetUnit, :SetOptions, :Release wait for combat to end; .state says "working", "missing", "refused" or "error"

Testing without the game: tools/harness/secrets.lua simulates secrets and combat in the stub client. STUB.Secrets.Enable() makes health secret and errors on misuse (ordering, joining, measuring, indexing a secret, or giving one to a widget call that won't take it); STUB.Secrets.Combat(true) is combat lockdown, with the in-combat secrets and the aura rule. STUB.Secrets.Reveal(v) shows the value behind a secret, for checks.
