NorgannonDB data specification — schema 1.4

NorgannonDB is an addon-neutral game database: quests, NPCs, objects, items, loot, vendors, spawns, area triggers, zones, maps, factions and tracking categories. Any addon may read it. It ships no UI and needs no other addon.

This document is the contract. Field names, units and meanings below are stable within a schema major version. Additive changes (new optional fields, new tables) bump the minor version. Anything that changes or removes the meaning of an existing field bumps the major version.

1. Loading and versioning

-- in your TOC:  ## OptionalDeps: NorgannonDB   (or ## Dependencies: NorgannonDB)
local DB = NorgannonDB
if not DB or not DB:RequireSchema(1, 1) then return end   -- major 1, at least minor 1
Field Meaning
NorgannonDB.schema { major = 1, minor = 2 }
NorgannonDB.info { flavor, interface, build, generated, sources = { {name, version, commit, license} } }
NorgannonDB:RequireSchema(major, minMinor) true if this data can serve a consumer written for that version; otherwise false, message
NorgannonDB:Get(kind, id) (1.1) the record with every field decoded; same table as NorgannonDB[kind][id]
NorgannonDB:Peek(kind, id) (1.1) read-only view for bulk scans: a record not decoded yet comes back as a temporary copy and stays packed
NorgannonDB:PeekLocale(kind, id) (1.1) the same for the active locale's entry (§4)

Schema history: 1.4 recipes (every crafting recipe: skill-up colours, product, reagents, where it is learned) and index.recipes. 1.3 instances (dungeons and raids, with wings, bosses in order, each boss's own loot and the quests for them), reference loot table chances filled into drops. 1.2 quest hidden / hiddenReason, the index tables (hidden quests are left out of them). 1.1 packed records (§2 "Packed records"), Get, Peek, PeekLocale.

2. Conventions

  • IDs are the game's own IDs: quest ID, creature entry, gameobject entry, item ID, AreaTable ID, faction ID, skill line ID, spell ID.
  • Zones are AreaTable IDs (areaId), never UiMapIDs. Use NorgannonDB.maps to convert.
  • Coordinates are percentages 0..100 of the zone's map in the target client's map frame (for Forever, the Forever map, which differs from Era in Mulgore, Eastern Plaguelands, Redridge Mountains and Stormwind City). {-1, -1} means "inside an instance in this zone, position unknown".
  • Spawn lists (SpawnList): { [areaId] = { {x, y, respawn, phase}, ... } }. respawn is seconds (nil/0 = unknown). phase is an optional phase ID.
  • Waypoint lists: { [areaId] = { { {x, y}, {x, y}, ... }, ... } }, one array per path.
  • Faction reaction: "A" friendly to Alliance, "H" friendly to Horde, "AH" friendly to both, nil hostile to both.
  • Masks: races and classes are bitmasks; nil or 0 means "no restriction". Race bits are NorgannonDB.enums.raceMaskById[raceId] (UnitRace's 3rd return). Forever's race bits go above 2^32, so test them with arithmetic, never with the 32-bit bit library: NorgannonDB.HasFlag(mask, flag) does mask % (2*flag) >= flag.
  • Chances are percentages (12.5 = 12.5%). 0 means "drops, chance unknown or conditional".
  • Lists are plain Lua arrays. Absent means empty. Records never contain empty tables.
  • Records are shared, read-only tables. Copy before mutating, or use corrections (§6).

Packed records (1.1). quests, npcs, objects, items and the active locale's quests hold every ID as a real table, so NorgannonDB.npcs[id], pairs(NorgannonDB.npcs) and record.field work as before. To keep memory low, a record's name is stored as is and its other fields are decoded the first time any of them is read; the decoded record then stays. What this means for consumers:

  • Iterating a whole kind and reading only name (or NorgannonDB:L(kind, id)) decodes nothing.
  • pairs(record) / next(record) on a record none of whose other fields has been read yet only sees name. Call NorgannonDB:Get(kind, id) first when you iterate a record's fields.
  • For scans that read more than name from many records once (building your own index), use NorgannonDB:Peek(kind, id): it does not keep the decoded records in memory.
  • NorgannonDB.provenance[kind][id] can still be read but cannot be iterated; use GetProvenance.

3.3 NorgannonDB.objects[objectId]

name, zone, spawns, waypoints (transports), factionTemplate, reaction, questStarts, questEnds, respawn, drops = { [itemId] = chance }.

3.4 NorgannonDB.items[itemId]

Field Type Meaning
name string enUS name
level, requiredLevel number item level, level to use
class, subClass number ItemClass / subclass
flags, foodType, ammoType number
startQuest questId quest started by this item

npcs[].drops, objects[].drops and npcs[].sells are the same data indexed the other way.

Categories — value is a required skill (herbs, mines, fish), a level (rares) or a reaction code (flight, innkeeper, vendor, repair, banker, auctioneer, stablemaster, battlemaster, spirithealer, mailbox, meetingstone, trainer, chests).

Instances (1.3) — keys such as "deadmines", "sm-cathedral", "aq40". Facts are authored once (tools/norgannondb/instances.py); bosses' loot and the quests are found by the build.

Field Shape Meaning
area areaId the instance's area (its name comes from the client, localized); missing for WoW Forever instances not yet seen
name string only when there is no area to name it
group, groupName, wing string wings of one instance share a group ("scarlet-monastery") and its groupName; wing is "Graveyard", "Upper", ...
size, raid number, true group size; raids
levels { min, max } the recommended level range (the game's group finder ranges)
bossLevels { min, max } the bosses' levels (capped at 60)
entrance { area, x, y } where the entrance is, on the parent zone's map
keys {itemIds} items that open the way (keys, the Scarlet Key, the Seal of Ascension, ...)
attunement string English text, shown as is
bosses { { id = npcId, loot = {itemIds} }, ... } in their usual order; loot is the boss's own loot (gear and recipes few others drop, quest items only it drops), best chance first; the chances are in npcs[id].drops
quests {questIds} quests filed under the instance, or about its creatures; for a wing, those about its bosses (or about no wing's)
forever true an instance WoW Forever added; mostly learned by the Collector
note string an authored remark

Recipes (1.4), keyed by the recipe's spell id (its localized name is the spell's name):

Field Shape Meaning
skill skill line id the profession (professions[skill] names it)
name string enUS name
levels { orange, yellow, green, grey } the skill where it turns each colour (grey: no more skill-ups)
learn number the skill needed to learn it (trainer, or the recipe item's requirement)
item, count itemId, number what it makes, and how many when not 1 (none for enchants)
reagents { {itemId, count}, ... }
trainers { [npcId] = copper } trainers who teach it, and their price
items {itemIds} recipe items that teach it (their vendors, drops and quest rewards are in items)
quests {questIds} quests that teach it
auto true learned with the profession or as the skill rises
forever true a recipe WoW Forever added (its sources come from the Collector)

The recipe list and skill ranges are WoW Forever's own (its client's SkillLineAbility and SpellEffect): recipes it retired are left out (the Alchemy healing potions, now First Aid's), and the recipes it added are in, with forever = true. A recipe added without reagents in the tables read takes the reagents of the classic recipe making the same item. Recipes with no known source and an unknown product are left out.

Drop chances (1.3): where a creature's drop of an item had an unknown chance (0) and the creature rolls a reference loot table holding the item, the table's chance fills it in; a chance of 0 inside a table is an equal share of what its listed chances leave (cmangos's rule).

4. Localization — NorgannonDB.locales[locale]

Only the client's locale is loaded. enUS lives in the base records.

locales.deDE = {
  quests  = { [id] = { name = "...", objectives = {lines}, description = "..." } },
  npcs    = { [id] = { name = "...", subName = "..." } },
  objects = { [id] = "name" },  items = { [id] = "name" },
  zones   = { [id] = "name" },  professions = { [id] = "name" },
}

NorgannonDB:L(kind, id, field) returns the localized value with enUS fallback.

5. Player-dependent variants

A few corrections depend on the player (for example a quest with a different starter for Horde). The base records are the Alliance/Warrior view. NorgannonDB.variants holds field overrides:

variants = {
  base    = { faction = "Alliance", class = "WARRIOR" },
  faction = { Horde = { quests = { [id] = { field = value | NorgannonDB.REMOVED } }, npcs = ... } },
  class   = { MAGE  = { quests = { ... } } },
}

At load NorgannonDB applies the player's overrides to the base records (NorgannonDB.appliedVariants says which). Addons that need the neutral data call NorgannonDB:GetVariantOverrides(axis, value).

6. Corrections (runtime additions)

Addons and data collectors may add or fix records without editing data files:

NorgannonDB:RegisterCorrection("MyAddon", "npcs", 1234, { spawns = { [12] = { {40.1, 52.3} } } })
NorgannonDB:RegisterCallback("CORRECTION_APPLIED", function(kind, id, owner) ... end)

Corrections merge field by field (a field is replaced, never deep-merged). NorgannonDB:GetProvenance(kind, id) reports where a record came from: "questie", "pfquest", "questie+pfquest", "collector" (only players have seen it), or the owner of the last correction.

7. Sources and precedence

The data is compiled offline by tools/norgannondb/build.py:

  1. QuestieDB (GPL-3.0), loaded through its own code so all of its corrections apply. It is the source of truth: any field it provides wins.
  2. pfQuest (MIT) fills fields QuestieDB lacks: drop chances, respawn timers, reference loot tables, area triggers, tracking categories, quest descriptions, vendor stock counts. pfQuest coordinates are projected into the target client's map frame first.
  3. If QuestieDB lists an item's drop or vendor sources, that list is authoritative and pfQuest only adds chances. pfQuest's lists are used only where QuestieDB has none.
  4. Entities only pfQuest knows are kept and marked "pfquest" in provenance. Consumers decide whether to trust them (the pfQuest adapter skips pfQuest-only quests).
  5. NorgannonDB Collector findings from real play are added last. They add to a record and never remove from it, and changing something QuestieDB provides takes repeated sightings.

Because it includes QuestieDB data, the compiled database is distributed under GPL-3.0.

A JSON export with the same structure (string keys) is written to dist/json/ for non-Lua tools.
