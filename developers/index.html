Build Forever add-ons without solving the hard parts again

Norgannon Core (version 1.26.2, folder NorgannonDB_Core) is the runtime every Norgannon add-on is built on. It solves the parts of writing for WoW Forever that every add-on runs into, so yours can be mostly the thing it's for, and look and behave like part of the family from the first build.

The Forever problems it solves

WoW Forever runs classic content on a modern client, with modern restrictions. These are the walls add-on authors hit first, and the Core call for each one.

The problem What the Core gives you
Classic functions are gone: GetSpellInfo, GetItemInfo, GetContainerItemInfo, UnitAura, the old quest log calls and dozens more. Core.Compat: 60 of them, with their classic answers, through the client's new calls. No globals are written, so other add-ons are left alone.
Version checks misread the client, so libraries take the wrong path. Core.Client: IsForever(), Flavor() and IsClassicWorld(), from the interface number.
Health is always secret, and about 90 values turn secret in combat, so comparing or doing maths on them throws an error. Core.Secret and UI.UnitBar: bars, text, colours and fades that let the client handle the secret value, so your code never has to read it.
Auras can't be read in combat. UI.UnitAuras: a unit's buffs and debuffs, drawn by the game inside a frame of yours, in combat too.
Characters have first and last names, so whispers to the name an event gave you can fail. Core.Names: the full name a whisper reaches, learned from chat, the guild roster and add-on messages.
Add-on messages are blocked during chat lockdown, and chat lines from add-ons may not reach chat in instances. Core.Net: messages wait for the lockdown to end, then go. Core:Say: when a line won't post, the chat box opens with it ready to send.
Protected calls fail in combat. Core:AfterCombat queues them, and Core:Restricted tells you which restriction is on and when it changes.

Everything else the Core gives you

  • One call to start. Core:NewAddon gives you the version check, saved variables with defaults and migrations, a slash command with help, a settings page, and a row in the Norgannon minimap list and the game's add-on menu.
  • The family look. Windows, lists, settings rows, buttons, inputs and colours that match every Norgannon add-on, with fonts that cover nine languages.
  • A safe way to call the game. WoW Forever's client hides some values and forbids some calls, more than Classic did. The Core's helpers turn errors and secret values into nil instead of breaking your add-on.
  • The map. Pins on the world map and the minimap, a compass across the top of the screen and a waypoint arrow, shared by every add-on, so they never fight over the same pins.
  • The game data, if you want it. Searches by name, quest and loot helpers over NorgannonDB. The Core runs without NorgannonDB, so add-ons that don't need the data don't pay for it.
  • Events and messages. Game events through one shared frame, and a message bus between add-ons.

Reading the game data

NorgannonDB, the game data, is an ordinary add-on with a written format, the database specification. You don't need the Core to read it:

-- TOC:  ## OptionalDeps: NorgannonDB   (or ## Dependencies: NorgannonDB)
local DB = NorgannonDB
if not DB or not DB:RequireSchema(1, 4) then return end

local quest = DB:Get("quests", 783)      -- A Threat Within
print(quest.name, quest.level)

Field names and meanings are stable within a major schema version, and new data only ever adds. NorgannonDB is free software under the GPL-3.0, because it contains data from QuestieDB. If you copy its data into your own add-on, that data stays under the GPL. Found something wrong or missing? Players can help fix it, and so can you on NorgannonDB's GitHub page.

Where to start

  1. Getting started: a working add-on in two files, and the rules Norgannon's own add-ons follow.
  2. What the client allows: what WoW Forever's client forbids, which values are secret, and how to work with them. Read this before you trust anything you know from retail or Classic.
  3. Core API: every function the Core promises to keep. Anything not listed there is internal.
  4. Database specification: NorgannonDB's tables and fields, if you read the game data.
  5. The Forever API reference: the client's own functions, events and widgets, as recorded in the game by a probe add-on rather than guessed from other clients. It includes a table of where each classic function went, and definitions for VS Code's Lua extension that flag calls that go secret in combat, are forbidden or are protected.

NorgannonTemplate is a small, complete add-on to copy from. Norgannon's tests load it on every build, so it always works with the current Core.

Versions

An add-on asks for the Core version it was written for: api = { 1, 20 } means "written for Core 1.20". It runs on any later 1.x, because a minor version only ever adds. A new major version may change things, and the Core says so in chat rather than failing quietly.

The licence, today

Read before you ship. NorgannonDB, the game data, is free software under the GPL-3.0. The Core's code is currently All Rights Reserved. The plan is to release it under an open licence before it's published for general use. Until then, ask before you release an add-on that depends on it.
